# Mode d'emploi — constitution de la requête

## 1. Objectif

Le but n'est pas de produire le texte le plus long, mais le dossier le plus **exact, autoportant, vérifiable, contradictoire et résistant à une lecture adverse** possible dans le délai.

Principe directeur :

~~~text
FAIT
→ TRACE PRIMAIRE
→ QUALIFICATION
→ RÈGLE
→ ÉCART
→ INCIDENCE
→ INCERTITUDE
→ REMÈDE / MESURE D'INSTRUCTION
~~~

## 2. Sources de vérité distinctes

Ne jamais fusionner silencieusement :

1. **requête** — moyens et conclusions ;
2. **bordereau** — pièces effectivement ou potentiellement produites ;
3. **inventaire probatoire** — univers plus large des traces ;
4. **chronologie détaillée** — ordre temporel et rattachement des actes/pièces ;
5. **Gmail / fichiers natifs / photographies / Drive** — sources primaires ;
6. **Corpus** — carte et travail préparatoire, jamais substitut aux pièces ;
7. **sources juridiques officielles** — règles et jurisprudence.

## 2 bis. Séparation data plane / control plane

Le dossier applique la séparation canonique du Corpus :

- **data plane** : requête, annexes, pièces, chronologie, fichiers, preuves, paquet remis ;
- **control plane** : checklist, présent protocole, audits, revue adverse, règles de gel, règles de dépôt.

Cette séparation est une forme de FractaCognition : le dossier ne se contente pas d'accumuler des données, il observe et contrôle la manière dont il se construit.

Le control plane n'établit pas le fond. Il doit produire des effets observables sur la qualité du data plane ; sinon il devient bureaucratique.

## 3. Cycle obligatoire pour chaque version

Avant de promouvoir une version :

~~~text
1. lire la version courante ;
2. lire la checklist courante ;
3. intégrer toute nouvelle trace pertinente ;
4. mettre à jour la chronologie ;
5. vérifier le mapping vers pièce(s) ;
6. vérifier le bordereau ;
7. vérifier l'inventaire ;
8. effectuer l'audit Gmail différentiel ;
9. rechercher les contradictions/adverse facts ;
10. vérifier les règles de droit sur source officielle ;
11. relire les conclusions ;
12. faire une passe "motifs de rejet" ;
13. seulement alors : promouvoir la version.
~~~

## 4. Règle Gmail

La messagerie est une source primaire majeure.

Avant gel final :

- rechercher toute la période utile depuis le **premier courriel à la préfecture du 10 septembre 2026 à 17:01:56** jusqu'au moment du gel ;
- interroger au minimum les domaines/adresses de la préfecture de Haute-Corse, du TA de Bastia, de la Sous-préfecture de Corte, du Défenseur des droits et les fils de la remplaçante lorsque le consentement ou l'accessibilité sont en cause ;
- inspecter les messages envoyés **et** reçus ;
- ne pas se limiter aux objets connus : effectuer aussi des recherches par dates, destinataires, expéditeurs et mots-clefs ;
- pour chaque message potentiellement pertinent : **INCLURE / RÉSERVE / EXCLURE avec motif** ;
- vérifier que tout message INCLUDE possède un identifiant de pièce ou un rattachement explicite à une pièce composite ;
- conserver l'ID Gmail / thread ID comme trace de provenance interne ;
- produire intégralement les messages invoqués lorsqu'ils fondent un fait matériel, sauf minimisation juridiquement nécessaire.

## 5. Règle chronologique

La chronologie doit être ordonnée :

~~~text
jour croissant
→ heure locale croissante dans chaque journée
→ événement
→ auteur / acteur
→ source primaire
→ pièce
→ statut de preuve
→ portée
→ limite / inconnu
~~~

Une heure inconnue reste « heure inconnue » et n'est jamais reconstruite artificiellement.

Distinguer :
- heure de l'événement ;
- heure d'émission ;
- heure de réception connue ;
- heure d'enregistrement administratif ;
- heure de connaissance dans le Corpus.

## 6. Règle de complétude

Pour chaque affirmation importante de la requête poser six questions :

1. Quelle est la **trace la plus primaire** ?
2. Est-elle **annexée** ou réellement accessible ?
3. Sa provenance est-elle vérifiable ?
4. Existe-t-il une trace **adverse ou contradictoire** ?
5. La requête qualifie-t-elle correctement ce que la pièce établit **et ce qu'elle n'établit pas** ?
6. La chronologie et le bordereau racontent-ils exactement la même chose ?

## 6 bis. Double lecture grand public / expert

Chaque grande section doit être lisible selon deux niveaux compatibles :

- **GP** : narration complète, définitions, contexte, finalité, moyens et enjeux ;
- **EXPERT** : textes, jurisprudence, pièces, qualifications et objections adverses.

Les deux niveaux doivent exprimer la même proposition et les mêmes réserves.

Une divergence GP/EXPERT est traitée comme un bug de dossier.

## 6 ter. Règles d'intelligibilité

### Grand public — budget attentionnel minimal

Le lecteur est supposé intelligent, mais pressé.

Règles :
- une phrase courte porte une idée principale ;
- le sujet, l'action et la conséquence doivent être identifiables immédiatement ;
- tout terme juridique est défini avant usage ;
- les acronymes sont développés à leur première occurrence ;
- les métaphores sont concrètes et servent uniquement à réduire la charge cognitive ;
- les phrases à tiroirs et doubles négations sont évitées ;
- chaque sous-section se termine par une conclusion explicite.

### Expert — niveau juriste junior

Le lecteur connaît le droit, mais pas nécessairement ce dossier ni cette branche spécialisée.

Règles :
- rappeler le rang de la norme ;
- citer la source ;
- expliquer le rôle de la règle ;
- identifier le fait auquel elle s'applique ;
- exposer le meilleur contre-argument ;
- expliquer pourquoi il est accepté, rejeté ou laissé ouvert ;
- écrire la conséquence procédurale ou contentieuse.

### Principe de Talleyrand

> Ce qui va sans dire va encore mieux en le disant.

Application :
- aucune prémisse décisive laissée implicite ;
- aucun « donc » sans chaîne écrite ;
- aucun pronom ambigu ;
- aucun changement de niveau sans transition ;
- aucune distinction importante supposée connue ;
- aucune intention attribuée sans source ;
- aucun « silence » transformé implicitement en « refus ».

Le but est de réduire les malentendus, pas seulement d'améliorer le style.

## 7. Règle de contradiction

Une pièce défavorable n'est jamais omise pour cette seule raison.

Si une trace contredit ou borne la thèse :
- la conserver ;
- la qualifier ;
- expliquer sa portée ;
- ne pas attendre que l'adversaire la découvre.

Exemple méthodologique : P-28 établit une réponse de la préfecture sur la consultation des pièces ; il interdit donc de résumer P-45 comme « silence total de l'État ».

## 8. Règle juridique

Toute proposition de droit portant le raisonnement doit être revérifiée sur une source officielle au moment du gel.

Séparer :
- texte applicable ;
- interprétation jurisprudentielle ;
- analogie ;
- argument proposé ;
- question ouverte.

Une analogie n'est jamais rédigée comme une règle certaine.

## 9. Règle de minimisation

Le dossier doit être complet mais non parasité.

Pour chaque pièce :
- **A** : nécessaire au noyau ;
- **B** : soutien utile ;
- **C** : contexte/réserve ;
- **D** : sensible, produire seulement si nécessité démontrée.

La chronologie peut mentionner une trace sans imposer sa production si elle n'est pas matériellement utile au moyen.

## 10. Règle de gel

Une version de dépôt n'existe que lorsque sont gelés ensemble :

~~~text
requête
+ annexes incorporées
+ bordereau
+ liste exacte des fichiers/pièces
+ SHA-256
+ canal(x) de remise
+ preuve(s) de réception
~~~

Après une première remise, ne jamais modifier rétroactivement l'objet déposé.

## 11. Kill-switches

Ne pas promouvoir une branche argumentative si :
- elle dépend d'un fait non suffisamment établi ;
- elle exige une règle de droit non vérifiée ;
- elle ajoute un grief après expiration du délai ;
- elle fragilise le noyau sans gain utile ;
- sa preuve essentielle n'est pas disponible ;
- elle mélange intérêt éditorial/politique et nécessité contentieuse.

## 12. Test final

Un juriste extérieur, ne connaissant ni le Corpus ni les conversations préparatoires, doit pouvoir :

1. comprendre la chronologie ;
2. retrouver chaque fait dans une pièce ;
3. comprendre chaque pièce sans convention interne ;
4. distinguer établi / rapporté / inféré / inconnu ;
5. identifier les moyens et leurs fondements ;
6. identifier les conclusions ;
7. voir immédiatement les points faibles et les mesures d'instruction demandées.

Si ce test échoue, le paquet n'est pas prêt.
